# 朱果宣传与下载页

无需前端依赖的静态网站，使用现有朱果素材。包含响应式宣传页、18 秒可重播宣传动画、键盘可操作的节奏预览、EXE 安装器与便携 ZIP 下载。动画为网页实时渲染，没有单独的 MP4，也不播放背景音乐。系统偏好减少动态效果时关闭装饰性运动。

## 本地预览

在仓库根目录运行 `node website/serve.cjs`，打开 http://127.0.0.1:4173。预览服务仅监听本机，且只公开白名单内文件。

## 生成下载与部署包

在 Windows 上运行 `./scripts/build-website.ps1`。它复用 `./package.ps1` 的统一打包流程：自动导出多尺寸品牌图标，执行应用构建和逻辑检查、真实控件渲染、便携包白名单与 SHA-256 校验，随后编译安装器、校验其内嵌压缩包，并在 `build/installer-preview.png` 输出真实安装控件的离线渲染图。普通打包与自动构建也会为每个版本生成同样的品牌安装包。版本号来自仓库 VERSION，网站构建自动更新网页下载链接与版本文案。

- `dist/TomatoFocus-<版本>-Setup.exe`：图形安装器；将应用安装到当前用户的 LocalAppData/Programs/TomatoFocus/<版本>，创建开始菜单快捷方式，可选创建桌面快捷方式。
- `dist/TomatoFocus-<版本>-win-x64.zip`：免安装便携版。
- `dist/TomatoFocus-website-<版本>.zip`：仅包含公开网页、图片、下载文件及 SHA-256 清单。

安装器不提权、不添加开机自启、不启动应用、不修改计时状态、不覆盖内容不同的同版本安装；更新已有快捷方式前保存备份。当前为轻量安装器，不注册到 Windows「已安装的应用」，卸载需退出应用后删除安装目录与快捷方式，用户状态默认保留。程序与安装器均未代码签名。自动验证覆盖内嵌载荷完整性；真实用户目录安装及快捷方式创建还需在干净 Windows 环境手动验收。

## GitHub Pages

推送 `main` 后，`.github/workflows/pages.yml` 在 Windows 环境构建并校验网站包，只解压公开白名单中的文件到 Pages 发布产物，再部署到 `github-pages` 环境。服务器配置、开发脚本和本地文件不会进入官网。正式版本使用 `v<版本>` 标签触发 `.github/workflows/release.yml`，标签必须与仓库 `VERSION` 完全一致。

下载二进制不纳入 Git，通过上述构建命令生成。发布前应清理发布目录中不再需要的旧版本，避免无意分发旧包；本脚本不会删除已有下载。

## 网站验证

完成构建后，在 `website/` 执行 `npm install`，安装 `package.json` 中指定版本的浏览器测试依赖。预览服务使用 `npm start`；另一个终端在同目录执行 `npm test`。测试使用本机 Chrome，覆盖响应式布局、动画重播、键盘操作、真实下载和减少动态效果设置。运行网站与桌面程序本身不需要 Node.js 或浏览器测试依赖。

## 部署模板

`deploy/` 提供 Ubuntu / Nginx 的内部验收、HTTPS、校验和回退模板。使用前将其中的 `example.com` 替换为自己的域名，并按 [部署说明](deploy/RUNBOOK.md) 配置服务器。仓库不包含具体服务器地址、DNS 账户信息或本机运维记录。

网站包通过明确的文件清单生成，只含当前版本下载和公开网页；`MANIFEST.sha256` 记录每个文件的哈希。发布时只上传网站 ZIP，不上传源码、部署配置或凭据。生成包不代表网站已部署或公网可用。

网站没有第三方 CDN、远程字体、登录、统计或后端接口，可直接托管于静态 Web 服务。
